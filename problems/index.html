If something goes wrong

Windows

"Windows protected your PC" – when running ClinicNest_setup.exe

The installer is not code-signed yet, so SmartScreen does not know it. Click More info, then Run anyway. The one-command install does not show this warning.

The download does not start or is blocked

Some office and hospital networks block download sites. The same files are on GitHub: ClinicNest releases. The one-command install tries both places by itself. Otherwise download on another network (e.g. a phone hotspot) and copy the file over.

The antivirus warns or removes ClinicNest

New, unsigned programs are sometimes flagged. Restore ClinicNest from the antivirus quarantine and add it as an exception, or use the one-command install (the download is checked against ClinicNest's signature).

Phones or other computers cannot open ClinicNest
  1. They must be on the same Wi-Fi / network as the ClinicNest computer – not on mobile data or a guest Wi-Fi.
  2. Windows Firewall: open Windows Security → Firewall & network protection → Allow an app through firewall, click Change settings and tick Private for ClinicNest / Java (OpenJDK Platform binary).
  3. The Wi-Fi must be set as a Private network (Settings → Network & internet → Wi-Fi → your network).
  4. Company security software (e.g. FortiClient, other firewalls) may block incoming connections: ask your IT.
"'irm' is not recognized as an internal or external command"

The line was pasted into Command Prompt, not PowerShell. Open Windows PowerShell and paste it there, or use the Command Prompt line shown on Install on Windows (it starts PowerShell for you).

"running scripts is disabled on this system"

Paste the command exactly as shown (irm … | iex) – it does not need script execution to be allowed. If your organisation blocks it, use the installer button instead.

PowerShell says it cannot download

Check the internet connection and try again in a few minutes. Behind a company proxy, use the installer button.

The browser does not open

Wait 30 seconds after the first start, then open http://localhost:8080 on that computer, or click Open ClinicNest in ClinicNest's window. If another program already uses port 8080, ClinicNest takes the next free one (8081, …) and keeps it – its window shows the address.

Mac

"ClinicNest cannot be opened" / "Apple could not verify…" – after the disk image

The app is not signed with Apple yet. Open System Settings → Privacy & Security, scroll down and click Open Anyway next to ClinicNest, then confirm. Needed once. The one-command install does not show this message.

Phones or other computers cannot open ClinicNest
  1. They must be on the same Wi-Fi as the Mac – not on mobile data or a guest Wi-Fi.
  2. System Settings → Privacy & Security → Local Network: switch ClinicNest on. (This is what the "find devices on your local network" question sets.)
  3. Company security software (e.g. FortiClient) may block incoming connections even when it looks switched off: ask your IT, or quit it while testing.
  4. The macOS firewall, if switched on (System Settings → Network → Firewall): allow incoming connections for ClinicNest.
The download does not start or is blocked

Some office and hospital networks block download sites. The same files are on GitHub: ClinicNest releases. The one-command install tries both places by itself.

"You can't open the application because it is not supported on this type of Mac" / Intel Mac

The disk image is for the other kind of Mac. Apple menu → About This Mac shows which it is: for "Chip: Apple M…" take ClinicNest.dmg, for "Processor: … Intel …" take ClinicNest-intel.dmg. The one-command install picks the right one by itself. See Install on a Mac.

Terminal says "Not installed: …"

The download could not be checked – it was incomplete or changed on the way. Nothing was installed. Run the command again; if it keeps happening, write to support@clinicnest.app.

The browser does not open

Wait 30 seconds after the first start, then open http://localhost:8080 on that Mac, or use ClinicNest's menu-bar icon → Open ClinicNest. If another program already uses port 8080, ClinicNest takes the next free one (8081, …) and keeps it – its window shows the address.

Linux

Phones or other computers cannot open ClinicNest
  1. They must be on the same Wi-Fi / network as the ClinicNest computer – not on mobile data or a guest Wi-Fi.
  2. The firewall of the ClinicNest computer may be closed for it. On Fedora and openSUSE:
    On Ubuntu, when its firewall (ufw) is switched on:
    If ClinicNest's window shows another number than 8080 in its address, use that number.
"needs a 64-bit Intel / AMD processor"

ClinicNest for Linux runs on computers with a 64-bit Intel or AMD processor. Computers with an ARM processor, such as a Raspberry Pi, are not supported yet.

"the program curl is needed" / "openssl is needed"

Install it and run the command again. On Ubuntu, Debian and Linux Mint: sudo apt install curl openssl; on Fedora: sudo dnf install curl openssl.

The terminal says "Not installed: …"

The download could not be checked – it was incomplete or changed on the way. Nothing was installed. Run the command again; if it keeps happening, write to support@clinicnest.app.

ClinicNest's window is gone

Closing the window only minimises it; ClinicNest keeps running. Bring it back from the dock or the list of open windows, or start ClinicNest from the applications menu again. Some desktops (GNOME) show no ClinicNest icon in the bar at the top.

The browser does not open

Wait 30 seconds after the first start, then open http://localhost:8080 on that computer, or click Open ClinicNest in ClinicNest's window. If another program already uses port 8080, ClinicNest takes the next free one (8081, …) and keeps it – its window shows the address.

Still stuck? Write to support@clinicnest.app.
